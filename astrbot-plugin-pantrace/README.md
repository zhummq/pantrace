# 盘迹网盘搜索 · AstrBot 插件

在 AstrBot（QQ 官方机器人 / OneBot）里用 `/搜` 命令搜索网盘资源；同时可以**静默监听指定群**，把群主/管理员发的分享自动收进库。搜索与入库的能力都在「盘迹 PanTrace」后端，本插件不接触后端的 apikey 和签名。

## 能力

- `/搜 关键词` —— 搜索全部平台
- `/搜 关键词 夸克,百度` —— 指定平台（支持中英文平台名）
- `/搜 关键词 夸克 2` —— 翻到第 2 页
- `/搜帮助` —— 查看用法
- **群消息采集**（可选，默认关闭）—— 监听指定群里群主/管理员发的网盘分享，提取链接和标题后入库

群聊（@机器人后发命令）和私聊都可用。结果带绝对链接、提取码、体积，长列表自动分页。

## 前置条件

1. PanTrace 后端已部署并有公网域名，`/api/search` 能正常返回结果（先浏览器验证：`https://你的域名/api/search?q=测试`）。后端**无需任何改动**——短链不需要，长链由 Markdown 藏起来。
2. AstrBot 已装好并配置了 QQ 官方机器人（或 OneBot/NapCat），推荐 v4.17+，对原生 Markdown 支持最稳。
3. QQ 机器人的**自定义 Markdown 能力**已全面放开（单聊、群聊都支持，无需单独申请模板）；频道场景仍需内邀开通。群聊/私聊场景直接可用。

## 安装

1. 把整个 `astrbot_plugin_pantrace` 目录（本目录）拷到 AstrBot 的 `data/plugins/` 下。

   ```bash
   cp -r astrbot-plugin-pantrace /path/to/AstrBot/data/plugins/astrbot_plugin_pantrace
   ```

2. 重启 AstrBot，或在 WebUI「插件」页点重载。

3. 装依赖：本插件只用 `aiohttp`（AstrBot 通常已自带）。若报 `ModuleNotFoundError: aiohttp`，在 AstrBot 环境执行：

   ```bash
   pip install aiohttp
   ```

4. 打开 WebUI「插件」→ 找到「盘迹网盘搜索」→ 配置，填写 **PanTrace 服务地址**，例如 `https://pan.example.com`（不含结尾斜杠）。其他项保持默认即可。保存并关闭。

5. 重载插件使配置生效。发 `/搜 三体` 验证。

## 群消息采集

群里有人发资源，库自己变厚。开启后插件静默旁听，**不回复、不拦截**，其他插件和 LLM 照常工作。

### 三道闸门

| 闸门 | 判据 | 拦掉什么 |
|---|---|---|
| 群 | `capture_groups` 里的群号；**空 = 一个都不采** | 无关群的闲聊 |
| 身份 | 消息事件里 `sender.role`，命中 `capture_roles` | 普通群友的随手转发 |
| 内容 | 消息里出现网盘域名 | 没链接的日常聊天（不上报，不占带宽） |

三道都过才上报。上报是攒批的（1.5 秒一批，每批最多 50 条），失败重试一次后丢弃——群里消息是流，攒着只会等网络恢复后灌进一堆过期数据。

### 后端准备

`backend/.env` 加一个令牌（**不是**给插件用 ADMIN_TOKEN）：

```ini
QQ_INGEST_ENABLED=true
QQ_INGEST_TOKEN=换成一段随机串
```

`QQ_INGEST_TOKEN` 留空会回退用 `ADMIN_TOKEN`；两个都空则只允许本机调用。

### 插件配置

WebUI「插件」→「盘迹网盘搜索」→ 配置：

| 项 | 填什么 |
|---|---|
| 群消息采集 | 开 |
| 监听的群号 | 群号纯数字，可填多个，例如 `123456`、`789012`。**必须填**：留空则一条都不采 |
| 采集哪些身份 | 默认 `owner` + `admin`（群主 + 管理员） |
| 上报令牌 | 与后端 `QQ_INGEST_TOKEN` 完全一致 |
| 采集后回执 | 调试期开；稳定后关，否则群里机器人老吭声会被嫌 |
| AI 结构化 | 默认开。用 AstrBot 已配置的大模型整理标题；没配模型就自动退回规则解析 |
| AI 结构化超时 | 默认 20 秒。一批消息的总预算，超时的部分退回规则解析 |
| 指定模型提供商 ID | 留空 = 用默认模型；建议填个便宜的小模型 |

保存后重载插件。

### 验证

1. 打开「采集后回执」。
2. 用**群主或管理员**账号，在目标群发一条：

   ```
   测试资源 4K
   https://pan.quark.cn/s/任意有效分享id
   提取码：1234
   ```

3. 群里应该回一句「已收录，稍后入库。」。
4. 到站点搜「测试资源」——搜得到，说明链路通了。
5. 把「采集后回执」关掉。

后端日志里同时会有一行：

```
QQ 采集：1 条消息（AI 结构化 1 条）→ 1 条链接，新增 1 / 更新 0
```

### AI 结构化（默认开）

群里很多分享长这样：标题写两行、提取码隔三行、尾巴挂一句「更多资源关注公众号」。纯正则只能靠字段名和长度去猜哪行是片名，经常猜出半截标题。

所以插件会先让 **AstrBot 已配置的大模型**读整条消息，输出

```json
{"items": [{"title": "漫长的季节 2023 4K", "shareUrl": "https://pan.quark.cn/s/xxx", "sharePwd": "k9m2"}]}
```

再由后端核对入库。但模型的权限被刻意压到最小：

| 字段 | 谁说了算 |
|---|---|
| `title` | **模型说了算**（它就是干这个的） |
| `shareUrl` | **原文说了算**。后端拿正则结果核对 `platform:pwd_id`，对不上就整条丢弃 |
| `sharePwd` | **原文说了算**。模型给的码必须在原文里出现过，否则用规则解析的 |

也就是说，模型把短链补全、把分享 id 记错一个字符、原文没写码却照着规律猜一个——这几种都不会进库。反过来，模型漏掉的链接会被正则补回来，**结构化只改善标题，不会减少入库数量**。

调用跑了这么久也没关系：AI 在后台攒批任务里跑，不在群消息处理函数里，不拖慢聊天；一批最多给 6 条消息过模型，整批共用一个总超时。任何失败（没配模型、超时、返回的不是 JSON）都静默退回规则解析，链接照样入库。

没配模型时日志里会出现一次：

```
pantrace: 没取到大模型，AI 结构化已跳过，本次改用规则解析。
```

不想消耗模型额度就把「AI 结构化」关掉，整条链路回到纯正则。

### NapCat 侧的必要条件

- **机器人账号必须在群里**，且不是被禁言/被踢的状态；
- NapCat 要上报群消息（默认会报，如果你改过 `messagePostFormat` 或做过消息过滤，确认群消息没被吞）；
- 机器人不需要是管理员。普通成员也能收到全部群消息——判定身份靠消息里的 `sender.role`，不需要额外权限。

如果配好了却一条都不进库，按这个顺序查：后端 `QQ_INGEST_TOKEN` 对不对 → 插件 `base_url` 通不通 → AstrBot 日志里有没有 `pantrace: 采集上报失败` → 群号填的是不是**群号**（不是群名、不是机器人 QQ）。

### 标题是怎么认出来的（规则解析）

AI 关闭或失败时走这套。插件只上报原文，标题由后端解析，覆盖群里常见的写法：

```
【4K修复】漫长的季节 2023     ← 标题行
导演：辛爽                    ← 元信息行，比标题短，不会顶掉它
链接：https://pan.quark.cn/s/xxx
提取码：abcd                  ← 码单独一行也能配上
夸克：https://pan.quark.cn/s/yyy 提取码 12ab
```

- 标题独占一行时，它会配给下面**同一段**（空行分段）里的链接；
- 链接行自带标题时优先用自带的（`三体 全集 https://…`）；
- 链接行只写平台名（`夸克 https://…`）不算标题，会用上一行的；
- 一条消息挂多个盘时，共用同一个标题；
- 提取码按"离它最近的链接"分配，一个码只给一条链接，不会跨链接乱配。

### 已知限制

- **合并转发的聊天记录**（多条消息打包转发）里层的链接拿不到。那种消息在协议层是 Forward 段，需要额外展开，当前不处理。
- **卡片消息**能挖标题和链接（`meta.news.title` + `jumpUrl`），但一个卡片通常只带一个链接。
- **身份缓存 10 分钟**：某人刚被撤管理员，10 分钟内发的消息仍可能被当成管理员。正常场景无所谓，敏感群可重载插件清缓存。
- **AI 只影响标题**：模型给的链接或提取码只要和原文对不上就会被丢掉，所以它写错不会产生死链，但也不会因为"模型觉得这条是广告"就过滤掉资源。要过滤得靠群白名单和身份白名单。
- 采集进来的资源**来源等级是 1**（和自建 TG 频道同级），搜索排序会比上游爬取的靠前。觉得太吵就在库里按来源筛。

## 内嵌 Skill

插件自带 `skills/pantrace-search` 技能：当用户用自然语言问"找某资源"时，AI 会据此理解平台对应关系、引导用户用 `/搜` 命令，并正确解读结果链接的时效性。技能随插件启用自动出现在 WebUI「技能」列表（来源显示为插件），可在人格的「技能能力」里勾选启用。

> 注意：Skill 只负责对话理解与引导，实际搜索由 `/搜` 命令执行。这也正是为什么单独装 Skill 搜不了资源——必须有本插件提供执行能力。

## 配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| base_url | `https://你的域名` | **必填**。PanTrace 后端根地址 |
| result_limit | 6 | 每次显示条数（1-10），QQ 消息不宜过长 |
| timeout | 80 | 搜索超时秒数。上游慢时接近 60 秒，别调太低 |
| cache_ttl | 300 | 结果缓存秒数，减少重复打上游 |
| cache_maxsize | 200 | 缓存条目上限 |
| capture_enabled | 关 | 群消息采集总闸。关掉后 `/搜` 照常可用 |
| capture_groups | 空 | 监听的群号，可多个。**留空 = 不采集任何群** |
| capture_roles | owner, admin | 采集哪些群身份 |
| ingest_token | 空 | 上报令牌，与后端 `QQ_INGEST_TOKEN` 一致 |
| capture_ack | 关 | 采集后是否在群里回一句「已收录」 |
| ai_structure | 开 | 用 AstrBot 的大模型结构化标题/链接/提取码。失败自动退回规则解析 |
| ai_timeout | 20 | AI 结构化一批消息的总预算（秒），5-60 |
| ai_provider | 空 | 指定模型提供商 ID。留空用默认模型 |

## 展示优化说明

搜索结果用 QQ 原生 Markdown 渲染（AstrBot v4.17+ 自动支持，失败会降级纯文本）。展示样式由用户实测选定——**每条独立展示**，不做分组、不加序号：

- 每条两行：加粗标题 + `[点我打开](链接)`，下一行是平台 + 大小；条目之间空一行。
- 链接目标藏着 `/go/<token>` 长串，聊天窗只显示「点我打开」四个字。**不需要后端短链**——Markdown 本身就完成了"缩短"。
- 有过几个改动版本（同标题合并分组、哈希分享码当文字、带圈序号①②③），用户实测后都弃用了，最终回到这个逐条列表样式。
- 如果机器人发出来是 `[点我打开](...)` 这样的源码文字，说明该机器人不被允许发原生 Markdown（框架已自动降级）——此时链接仍可长按复制，功能不受影响。

效果示例：
```
🔍 尸兄　·　1000 条

尸兄 点我打开
夸克网盘　18.7GB

尸兄 点我打开
夸克网盘　18.7GB

尸兄！ 点我打开
阿里云盘　7.6GB

———
下一页 /搜 尸兄 3　·　打开后请先转存到自己的网盘 · 链接约 30 分钟有效
```

## 为什么链接点开是个过渡页

PanTrace 启用了「点击时转存」：结果里的链接是带签名的 `/go/<token>`，点击后网页转存并跳转到网盘，链接默认只活 30 分钟。设计如此，目的是逼用户当场转存到自己的网盘。因此要明确告诉用户：拿到链接尽快打开、打开后先转存。

## 常见问题

- **"连不上搜索服务"**：`base_url` 填错，或后端没启动/防火墙没放行。
- **"搜索服务返回 504"**：后端上游超时或签名失效。签名失效需要管理员重新抓 `x-idr-sign` 写入后端 `.env`，用户重试无用，插件会原样透传这条提示。
- **命令没反应**：确认插件已启用、QQ 机器人有收发消息权限；群里需按 AstrBot 配置 @机器人或使用唤醒前缀。
- **发的链接用户打不开**：确认 `base_url` 是公网可达的域名（不能是 `127.0.0.1` 或内网 IP），插件会把 `/go/xxx` 拼成绝对地址。
